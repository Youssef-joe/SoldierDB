Section 1

The field manual

Every layer is written from the page up, with tests against an in-memory oracle. No borrowed storage engine, no magic.

FM 1-01

Crash-safe page store

A file of 4 KiB pages. Commits write the inactive meta page last and fsync it, so a crash always leaves one valid root to recover from.

FM 1-02

Copy-on-write B+tree

Lookups, ordered range scans, splits and merges. A mutation never touches a committed page; freed pages return through a persistent free list.

FM 1-03

Atomic transactions

BEGIN, COMMIT, ROLLBACK. Writes are buffered and published as one batch behind a single meta-page flip.

FM 1-04

A real SQL front end

Hand-written lexer and recursive-descent parser. Filters, ORDER BY, LIMIT, aggregates, GROUP BY / HAVING, primary keys, UNIQUE, NOT NULL and defaults.

FM 1-05

Vector search

Fixed-dimension VECTOR(n) columns and distance functions, so you can rank rows by similarity right in SQL.

FM 1-06

One engine, three languages

A handle-based C ABI with clear memory ownership, wrapped by a safe Rust crate and an RAII C++ client. Each has its own CLI.

Section 3

Your orders

Requires Go 1.24+. Rust and a C++20 toolchain are only needed for the clients.

Order 1 · Report for duty
# clone, test and start the SQL shell
git clone https://github.com/Youssef-joe/SoldierDB
cd SoldierDB
make test
make run
Order 2 · Hold the line
CREATE TABLE users (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL, age INTEGER);
INSERT INTO users VALUES (1, 'Ada', 36), (2, 'Grace', 45);
SELECT name, age FROM users WHERE age > 40;
Order 3 · Find the nearest
CREATE TABLE docs (id INTEGER PRIMARY KEY, embedding VECTOR(3));
SELECT id FROM docs
ORDER BY cosine_distance(embedding, VECTOR(1, 0, 0))
LIMIT 10;
Order 4 · Full inspection
# fmt check, Go tests, then the C, Rust and C++ clients
make check

# or build just the shared library + header
make shared
